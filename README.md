# Galleria

A three-dimensional gallery room. Fifteen masterworks hang on a wall in
period-appropriate frames, lit by minimalist track lamps; the camera walks the
wall to reach each one, and steps in for a close-up where the work's didactic
is lettered onto the plaster beside it.

Built on the [Frontend Mentor](https://www.frontendmentor.io) *Galleria
slideshow site* challenge — see [README-Project.md](./README-Project.md) for
the original brief.

## What this project is exploring

This is a testbed for **uiskill** — building a real interface against a design
system that was generated from an existing site rather than written by hand.

The system arrived as a package of tokens, type scale, spacing grid, motion
curves and component patterns, and the whole application is built against it:
the ivory paper ground, the ink type, the restrained gold accent, the
Cormorant / Jost / Space Mono pairing, the 4px spacing grid and the
`cubic-bezier(.22, 1, .36, 1)` easing all trace back to it.

Two things worth recording about working this way:

- **The generated tokens are not all equally trustworthy.** The extraction
  reported `accent: #ffffff` and a default radius of `3.6vw` — artifacts, not
  intent, since a white accent on an ivory ground is invisible. The CSS custom
  properties captured from the live site (`--studio-ink-primary`,
  `--studio-accent-gold`, `--studio-bg-paper`) described the real design, and
  those are what the build follows.
- **A design system says nothing about a room.** It covers surfaces, type and
  motion. Lighting, frame profiles, hang height and camera work had to be
  reasoned about from how galleries actually behave, using the system only for
  the palette and the overlay UI.

## Getting started

```bash
npm install
npm run dev          # http://localhost:3000
```

Other scripts:

```bash
npm run build            # production build
npm run measure:images   # regenerate src/lib/image-sizes.json
```

## How it is put together

```
src/
├── app/
│   ├── layout.js            # fonts, Lenis, the persistent 3D stage
│   ├── page.js              # index: the room in profile + drifting works
│   └── slideshow/page.js    # the room head-on, close-up, lightbox
├── components/
│   ├── gallery3d/           # the room
│   └── Nav, Footer, MaskedText, Reveal, Icon
└── lib/
    ├── paintings.js         # data + measured image dimensions
    └── image-sizes.json     # generated by measure:images
```

### One room, two routes

The canvas lives in the root layout, not in either page. Next keeps a layout
mounted across navigations, so moving between the index and the slideshow never
unmounts it — which is what lets the camera fly from the oblique preview into
the head-on view instead of cutting. Each page just declares which viewpoint it
wants and hands over an element for the canvas to be clipped to.

The canvas is always full-viewport and **clipped**, never resized: resizing it
would make the renderer reallocate its drawing buffer on every frame of the
transition.

### Sizing and format

Canvases are shaped by `images.gallery` — the whole artwork — so nothing is
cropped. Every work is given the same **area** rather than the same height, so
a frieze comes out wide and low and a portrait tall and narrow, while none
dominates and none disappears.

> **Known limitation.** The bundled assets are themselves crops. Even the best
> file for *The Great Wave off Kanagawa* is missing 23% of the print's width,
> so some works still look tight. Fixing that needs new source images, not
> code: drop replacements at the same paths and re-run `npm run measure:images`
> — the canvas takes its shape from the file.

### Lighting

Three fixtures cover the work in view and its neighbours, rather than one lamp
per painting, which would mean fifteen shadow maps for a scene that only ever
shows three works at a time. Slots are assigned by channel so stepping along
the wall retires a single lamp, and lamps **switch** rather than slide — a
light that travels drags its pool across everything in between.

Only the work on screen is lit. The two neighbouring fixtures stay mounted but
dark on purpose: keeping them in the scene is what lets a lamp cross-fade in
place. In close-up the active lamp swings its head over to the didactic and its
spotlight follows, opening its beam so the work beside it does not fall dark.

## Accessibility and motion

Reading matter stays in the DOM rather than the canvas, so it remains
selectable and reachable by assistive technology. `prefers-reduced-motion` is
respected throughout, including a specific override for the index marquee,
which a blanket `animation-duration: 0.01ms` would otherwise freeze mid-travel.
